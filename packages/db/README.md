# @momentum/db

Data layer for Momentum — Drizzle ORM targeting Cloudflare D1 (SQLite).

## Schema

8 tables total. The first 4 are Better-Auth's required schema (matching its
D1/SQLite adapter). The last 4 are Momentum's application tables.

| Table          | Purpose                                          |
| -------------- | ------------------------------------------------ |
| `user`         | Better-Auth user + Momentum fields (username, timezone) |
| `session`      | Better-Auth sessions                             |
| `account`      | Better-Auth OAuth/password accounts              |
| `verification` | Better-Auth email verification / reset tokens    |
| `season`       | Monthly seasons with target rating + reward      |
| `project`      | User-owned task groupings                        |
| `task`         | Recurring task definition (immutable target/unit/weight) |
| `task_log`     | Per-day log entry for a task (actual + computed score) |

### Constraints

- **Foreign keys**: all FK references use `ON DELETE CASCADE`. Deleting a user
  cascades to seasons, projects → tasks → task_logs.
- **CHECK constraints**:
  - `season.target_rating` ∈ [0, 10]
  - `task.target_value` > 0
  - `task.unit` ∈ ('km', 'hours', 'pages', 'reps', 'count')
  - `task.importance_weight` ∈ [1, 5]
- **Unique indexes**:
  - `user.email`, `user.username`
  - `session.token`
  - `(task_log.task_id, task_log.date)` — one log per task per day

### Indexes

| Index                          | Columns                              |
| ------------------------------ | ------------------------------------ |
| `idx_season_user`              | `season.user_id`                     |
| `idx_season_dates`             | `season.start_date, season.end_date` |
| `idx_project_user`             | `project.user_id`                    |
| `idx_task_user_project_sort`   | `task.user_id, task.project_id, task.sort_order` |
| `uniq_task_log_task_date`      | `task_log.task_id, task_log.date` (unique) |
| `idx_task_log_user_date`       | `task_log.user_id, task_log.date`    |
| `idx_session_user`             | `session.user_id`                    |
| `idx_account_user`             | `account.user_id`                    |

## Migrations

Migrations are generated by `drizzle-kit generate` and applied by
`wrangler d1 migrations apply`. No force-push or data-loss commands are used
anywhere in the pipeline.

```bash
# Generate a new migration from schema changes
cd packages/db
npx drizzle-kit generate

# Apply to local D1 (miniflare emulation)
cd apps/api
npx wrangler d1 migrations apply momentum-local --local

# Apply to remote D1 (production)
npx wrangler d1 migrations apply momentum-prod --remote
```

## Scoped Query Helper — MANDATORY

**D1/SQLite has no Postgres-style Row-Level Security.** To prevent accidental
cross-user data access from a forgotten `WHERE user_id = ?` clause, every
query in Momentum MUST go through the `ScopedDb` helper.

### How to use

```typescript
import { createScopedDb } from "@momentum/db";

// In a route handler:
const scoped = await createScopedDb(c.env.DB, c.get("userId"));

// All methods on `scoped` automatically filter by userId:
const seasons = await scoped.seasons();
const project = await scoped.projectById(id);
const task = await scoped.insertTask({ projectId, title, ... });
await scoped.deleteProject(id);
```

`createScopedDb` does two things:
1. Runs `PRAGMA foreign_keys = ON;` to enable FK enforcement for the request.
2. Returns a `ScopedDb` instance that injects `WHERE user_id = ?` into every
   query.

### What NOT to do

```typescript
// BAD — raw Drizzle access, no userId filter, no FK pragma
import { createDb } from "@momentum/db";
const db = createDb(c.env.DB);
const seasons = await db.select().from(schema.season); // NO USER FILTER!

// BAD — even with a manual filter, FK pragma is not enabled
const db = createDb(c.env.DB);
const seasons = await db.select().from(schema.season).where(eq(schema.season.userId, userId));
```

`createDb` is exported ONLY for Better-Auth's internal use (Better-Auth
manages its own queries and table access). Application code must NEVER use it
directly.

### Adding new queries

If `ScopedDb` doesn't have a method you need, **add a method to `ScopedDb`**
in `packages/db/src/scoped.ts`. Do not bypass the helper with raw queries.

## Foreign Key Enforcement

D1 enables FK enforcement by default on remote databases. However, local
emulation (miniflare / better-sqlite3) has it **off** by default.

`createScopedDb` runs `PRAGMA foreign_keys = ON;` at the start of every
request to ensure consistent behavior across local and remote environments.
This is cheap (a single pragma statement) and idempotent.

## D1 Time Travel

Time Travel is **enabled by default** on all Cloudflare D1 databases. No
action is needed to enable it. It retains up to 30 days of history.

Time Travel is a **remote-only** feature — local D1 emulation (miniflare)
does not support it.

```bash
# Get a bookmark for a specific point in time
npx wrangler d1 time-travel info momentum-prod --timestamp 2024-01-15T10:00:00Z

# Restore to a bookmark
npx wrangler d1 time-travel restore momentum-prod --bookmark <bookmark-id>
```

## Better-Auth Integration

Better-Auth is integrated in `apps/api/src/lib/auth.ts`. The `user`, `session`,
`account`, and `verification` tables in this package match Better-Auth's
expected SQLite schema. Key points:

1. **Timestamp columns use `integer({ mode: "timestamp" })`** (not `text`).
   Better-Auth internally creates `Date` objects for `created_at`/`updated_at`/
   `expires_at`. D1's `bind()` rejects `Date` objects, so the columns must use
   Drizzle's timestamp mode which serializes `Date` ↔ integer (Unix seconds).
   The migration uses `(unixepoch())` as the default.
2. **`transaction: false`** in the drizzle adapter config — D1 doesn't support
   multi-statement transactions in a single call.
3. **`usePlural: false`** — table names are singular (`user`, `session`, etc.)
   to match Better-Auth's defaults.
4. **Additional fields**: `username` (required, unique, regex-validated) and
   `timezone` (optional, default "Asia/Karachi") are registered via
   `user.additionalFields` in the Better-Auth config.
5. **Application queries** continue to use `ScopedDb` (the userId-scoped helper).
   Better-Auth uses the raw `Database` (via `createDb`) for its own tables —
   this is the only sanctioned use of `createDb` in application code.

## Environment Variables

| Variable             | Where                | Purpose                                      |
| -------------------- | -------------------- | -------------------------------------------- |
| `DB` (binding)       | `wrangler.toml`      | D1 database binding                          |
| `BETTER_AUTH_SECRET` | `.dev.vars` / secret | 32+ char random string; signs session tokens |
| `BETTER_AUTH_URL`    | `wrangler.toml`      | Public URL of the API (e.g. `https://api.momentum.app`) |
| `RESEND_API_KEY`     | `.dev.vars` / secret | Resend API key for email delivery; empty = dev no-op |
| `FROM_EMAIL`         | `wrangler.toml`      | Sender address (must be verified in Resend)  |
| `APP_ENV`            | `wrangler.toml`      | `"local"` or `"production"` (controls cookie `secure` flag) |
